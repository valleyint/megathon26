# Cascaded Multi-Scorer Retrieval and Hierarchical VLM Verification System

## 1. System Overview and Master Flowchart

The system addresses extreme multi-label category suggestion for Wikimedia Commons by structuring inference into a three-stage cascaded retrieve-and-rerank pipeline. Stage 1 generates a high-recall candidate pool across millions of categories in bounded sub-50ms time. Stage 2 injects metadata-driven event categories, enforces chronological and spatial consistency, and suppresses redundant ancestors along the category Directed Acyclic Graph (DAG). Stage 3 executes fine-grained visual verification and grounding using an ultra-compact Vision-Language Model (VLM) to produce ranked suggestions with human-auditable explanations.

## 2. Stage 1: High-Recall Multi-Scorer Candidate Generation

Stage 1 extracts normalized multimodal features and queries large-scale index structures to narrow millions of potential Commons categories $\vert{}\mathcal{C}\vert{}$ down to a manageable candidate pool $C_{\text{cand}}$ in under 50 ms.

### Shared Feature Representation

All visual operations share a single forward pass through a frozen vision-language backbone $f_\theta$ (SigLIP or CLIP ViT-B/16):


$$z_x = \frac{f_\theta(x)}{\Vert{}f_\theta(x)\Vert{}_2} \in \mathbb{R}^d$$


Because $z_x$ is computed once and cached, Scorers 1, 2, and 3 run concurrently without extra vision encoder overhead.

### Scorer 1: Instance Retrieval ($k$-NN)

* **Objective:** Identify categories through visual consensus from historical images depicting identical landmarks, artworks, species, or objects.


* **Index Configuration:** Pre-compute visual vectors $z_i$ across all historical training images and index them using FAISS with Inverted File Product Quantization (`IndexIVFPQ`). Quantizing to 64 bytes per vector compresses $10^8$ images to approximately 6.4 GB of RAM while delivering sub-10ms inner-product searches.


* **Consensus Formulation:** Retrieve the $K = 50$ nearest visual neighbors $\mathcal{N}_K(x)$ and compute temperature-scaled consensus scores:



$$S_{\text{knn}}(c \mid x) = \frac{\sum_{i \in \mathcal{N}_K(x)} \exp(z_x^\top z_i / \tau) \cdot \mathbb{I}[c \in Y_i]}{\sum_{i \in \mathcal{N}_K(x)} \exp(z_x^\top z_i / \tau)}$$



where $\tau \in [0.05, 0.1]$ and $\mathbb{I}[c \in Y_i] = 1$ if neighbor $i$ is tagged with category $c$.


* **Continual Learning:** When new uploads are accepted by editors, append their normalized vectors directly to the FAISS index with zero model retraining. Neighboring images serve directly as visual explanations in the user interface.



### Scorer 2: Zero-Shot Text Prototypes

* **Objective:** Cover long-tail, unrepresented, or newly created categories that have zero historical training images.


* **Prototype Generation:** Pass category titles, alternate labels, and redirects through the text tower $g_\theta$ matching the vision backbone. Category strings are formatted using structured prompt templates (`"a Wikimedia Commons photograph categorized under {category_name}"`). Precomputed prototype vectors $t_c = g_\theta(\text{text}) / \Vert{}g_\theta(\text{text})\Vert{}_2$ are stored in a category matrix $T \in \mathbb{R}^{\vert{}\mathcal{C}\vert{} \times d}$.


* **Scoring Formulation:** Compute direct inner-product similarity against the query image embedding:



$$s_{\text{txt}}(c \mid x) = z_x^\top t_c$$


* **On-the-Fly Category Ingestion:** When a category is created, compute its text embedding $t_{\text{new}}$ and append it to $T$ in memory. The category becomes retrievable immediately.



### Scorer 3: Supervised Multi-Label Head (Optional / Head Calibration)

* **Objective:** Calibrate empirical probabilities for frequent categories ($n \ge n_{\min} \in [20, 50]$).


* **Architecture:** A linear head mapping $z_x$ to per-category sigmoid probabilities $p_c = \sigma(w_c^\top z_x + b_c)$. Classifier weights $W$ are initialized directly from precomputed text prototypes ($w_c^{(0)} = t_c$) to align representations before optimization.


* **Asymmetric Loss (ASL):** Trained with margin-based probability shifting to prevent unlabelled positive categories from being penalized as negative examples:



$$\mathcal{L}_{\text{ASL}} = -\sum_{c \in \mathcal{C}_{\text{sup}}} \left[ y_c (1 - p_c)^{\gamma_+} \log(p_c) + (1 - y_c) (p_{c,m})^{\gamma_-} \log(1 - p_{c,m}) \right]$$



where $p_{c,m} = \max(p_c - m, 0)$ with hyperparameters $\gamma_+ = 0$, $\gamma_- = 4$, and margin $m = 0.05$.



### Candidate Aggregation

Extract the top candidates from each active scorer to form the Stage 1 pool:


$$C_{\text{visual}} = \text{Top-50}(S_{\text{knn}}) \cup \text{Top-50}(s_{\text{txt}}) \cup \text{Top-50}(p_c)$$


This restricts downstream processing to 30–50 unique candidate categories, guaranteeing bounded latency.

### Proactive Event Discovery Logic

Visual features fail to discriminate specific events from generic scenes (e.g., distinguishing a demonstration from *2023 French pension reform strikes in Paris*).

1. **Metadata Parsing:** Extract EXIF `DateTimeOriginal` to isolate the 4-digit year ($Y$). Convert GPS latitude and longitude into administrative regions via an offline KD-tree lookup (avoiding remote API latency). Clean wikitext to remove templates and license boilerplate.


2. **Taxonomic Event Synthesis:** Pass the top visual concepts from Stage 1 along with parsed date, city, and title text into a fast text LLM (e.g., quantized Llama-3-8B). The LLM generates standard Commons event syntax hypotheses:


* `Category:[Topic] in [City] in [YYYY]`
* `Category:[YYYY] [Official Event Name]`


3. **Database Grounding:** Match generated hypotheses against a local Commons event sub-index using reciprocal rank fusion (BM25 + text prototypes). Snap queries strictly to verified categories existing within the Wikimedia database, eliminating hallucinations.



### Taxonomic Graph Pruning (DAG Optimization)

Commons cataloging rules instruct editors to categorize under the most specific applicable category rather than all ancestor nodes.

* Query the in-memory directed category graph for ancestor-descendant links across $C_{\text{pool}}$.


* Pre-process cycles using Tarjan's Strongly Connected Components algorithm to ensure acyclic traversals.


* **Suppression Rule:**

$$\text{Retain } c \in C_{\text{pool}} \iff \neg \exists \, d \in \left(\text{Descendants}(c) \cap C_{\text{pool}}\right) \text{ such that } s(d) \ge \tau_{\text{child}}$$


* If child category $d$ has high confidence ($s(d) \ge 0.35$), prune parent $c$. If no child triggers, retain parent $c$ as a safe, broad fallback.

### Stage 3 Implementation Details

1. **Sibling Partitioning:** Group competing leaf nodes sharing parent classes (e.g., distinguishing *Gothic Revival architecture* from *Rayonnant Gothic*).


2. **Constrained Single-Turn VLM Pass:** Pass the image alongside the candidate set into a lightweight VLM (e.g., Florence-2-base, 0.23B parameters) configured with grammar-constrained decoding (JSON schema). Restricting generation to binary verification flags and visual evidence tokens bounds inference latency to under 50 ms.


3. **Calibrated Score Fusion:** Combine early retrieval scores with VLM verification confidence:



$$s_{\text{final}}(c \mid x, m) = \alpha \cdot s_{\text{prior}}(c) + \beta \cdot s_{\text{VLM}}(c \mid x)$$



Candidates marked as ungrounded receive zero weight and are removed from suggestions.


4. **Explainability Audit Trail:** Retain the VLM's visual evidence phrase (e.g., *"Pointed ribbed vaulting and lancet windows verified"*) alongside the category in the user interface to satisfy the open auditability rubric requirement.

## 5. Latency, Serving, and Continual Learning Budget

Commons processes $10^4$ to $10^5$ uploads per day, requiring an average throughput of approximately 1 image/s with bounded computational overhead.

### Latency Profile per Upload

| Pipeline Step | Execution Component | Latency (GPU) | Latency (CPU) |
| --- | --- | --- | --- |
| **Stage 1: Vision Forward Pass** | SigLIP / ViT-B/16 ($z_x$ embedding)

 | 18 – 24 ms | 70 – 110 ms |
| **Stage 1: Scorer 1 ($k$-NN)** | FAISS `IndexIVFPQ` ($K=50$ lookup)

 | 3 – 5 ms | 6 – 12 ms |
| **Stage 1: Scorer 2 (Zero-Shot)** | Matrix product $z_x^\top T$ ($50\text{k}$ categories)

 | 1 – 2 ms | 4 – 8 ms |
| **Stage 2: Metadata & Geocoding** | Regex extraction + offline KD-tree lookup

 | 1 – 2 ms | 1 – 2 ms |
| **Stage 2: Event Query & BM25** | LLM hypothesis + lexical/dense lookup

 | 40 – 70 ms | 120 – 180 ms |
| **Stage 2: Category DAG Pruning** | In-memory graph traversal & ancestor drop

 | 1 – 3 ms | 2 – 4 ms |
| **Stage 3: VLM Verification** | Constrained Florence-2 forward pass

 | 40 – 60 ms | 180 – 260 ms |
| **Total End-to-End Latency** |  | **104 – 166 ms** | **383 – 576 ms** |

Both GPU and CPU profiles operate comfortably below the 1,000 ms ceiling, sustaining 6 to 10 images/s on a single worker and exceeding the 1 image/s volume requirement.

### Memory & Index Footprint

* **Historical Images:** Compressed to 64 bytes/vector using Product Quantization ($10^7$ images require $\approx 640$ MB; $10^8$ images require $\approx 6.4$ GB RAM).


* **Category Text Prototypes:** 50,000 categories at 768-d float16 require $\approx 76.8$ MB RAM.


* **Category Graph:** In-memory adjacency dictionaries across millions of Commons categories consume $\approx 350$ MB RAM.



### Continual Learning Mechanics

* **Instant Index Appends:** New accepted uploads are added directly to the FAISS index without retraining the backbone.


* **Instant Category Additions:** Newly created categories are embedded via text encoder $g_\theta$ and appended to prototype matrix $T$, enabling immediate zero-shot discovery.


* **Negative Feedback Loop:** Editor rejections are logged as hard negatives to calibrate candidate score thresholds.

## 6. Evaluation Protocol and Rubric Alignment

Because editors assign multiple categories and the label space is large, single-label accuracy is inapplicable. Evaluation follows ranking metrics over top-$k$ suggestions $\hat{Y}_k(x, m)$ against editor-assigned ground truth $Y(x)$:


$$P@k = \frac{\vert{}\hat{Y}_k \cap Y\vert{}}{k}, \quad R@k = \frac{\vert{}\hat{Y}_k \cap Y\vert{}}{\vert{}Y\vert{}}, \quad F1@k = \frac{2 \cdot P@k \cdot R@k}{P@k + R@k}$$


Mean Average Precision (mAP) is evaluated across categories, accompanied by hierarchy-aware precision where predicted ancestors/descendants receive partial credit.

### Protocol & Validation Splits

* **Temporal Hold-Out:** Train on earlier uploads and test on later uploads to evaluate true generalization over time.


* **Deduplication:** Remove near-duplicates across splits using perceptual hashing (pHash) and cosine similarity thresholds ($>0.92$) to prevent data leakage.


* **Stratified Breakdown:** Report results separated across head, torso, and tail frequencies, as well as category semantics (objects, scenes, events, abstract concepts).
